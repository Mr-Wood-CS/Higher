# Testing Programs That Use Arrays

Think about where a mistake might be hidden. For example, a loop might miss the last item in an array.

<table class="test-plan-table">
  <thead>
    <tr>
      <th scope="col">Program task</th>
      <th scope="col">Useful tests</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Find a value using a <strong>linear search</strong>.</td>
      <td>Put the value first, in the middle, and last. Also search for a value that is not there.</td>
    </tr>
    <tr>
      <td>Find the <strong>maximum or minimum</strong>.</td>
      <td>Put the answer at different positions. Also try an array where all values are equal.</td>
    </tr>
    <tr>
      <td><strong>Count occurrences</strong> of a value.</td>
      <td>Try no matches, one match, several matches, and every item matching.</td>
    </tr>
    <tr>
      <td>Display information from <strong>records</strong>.</td>
      <td>Check that the displayed name and score belong to the same person.</td>
    </tr>
  </tbody>
</table>

For example, the maximum in `[14, 9, 21]` is `21`. If a program reports `14`, check whether its loop reaches the last item.

Choose tests that fit the stated rules. Only test an empty array or negative numbers if the program is required to handle them.
