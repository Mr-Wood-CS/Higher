# Choosing Test Data

You will already have met **normal**, **extreme**, and **exceptional** test data. They are useful when building your Higher test plan.

| Type | What it means | Example for a mark from 0 to 100 |
|---|---|---|
| **Normal** | A typical value that is allowed. | `65` |
| **Extreme** | The lowest or highest value that is allowed. | `0` and `100` |
| **Exceptional** | A value or entry that is not allowed. | `-1`, `101`, `hello`, or an empty entry |

For this program, `0` and `100` must be **accepted**. Values such as `-1` and `101` must be **rejected**.

!!! note "Remember"

    Extreme values are still valid. They sit at the limits of the allowed range.

    Exceptional values break an input rule.

## Choosing Data to Test a Decision

Normal, extreme and exceptional data help you check input rules. You should also choose values that check whether the program makes the correct decisions.

For example, a program accepts whole-number marks from `0` to `100`, and a mark of `50` or above is a pass. Testing `0` and `100` checks the input limits, but you should also test `49`, `50` and `51` to check the pass decision.

| Mark | Expected result | Why use it? |
|---|---|---|
| `49` | `Not yet passed` | Just below the pass mark. |
| `50` | `Pass` | Exactly at the pass mark. |
| `51` | `Pass` | Just above the pass mark. |

This is useful for spotting a mistake such as using `> 50` instead of `>= 50`.

These are valid marks, but they are not the lowest and highest allowed inputs. They test the **pass decision** rather than the ends of the input range.
