# Sub-programs: Procedures and Functions

!!! info "What you need to know"

    You must be able to describe, exemplify and implement sub-programs defined
    by their **name** and **arguments (inputs and outputs)**, including both
    **procedures** and **functions**.

A sub-program is a named, reusable module that performs one clear task. Using
sub-programs supports modular design and makes code easier to test and maintain.

## Procedures

A procedure performs a task but does not return a value for use in an
expression.

```python linenums="1"
def display_result(name, score):
    print(f"{name} scored {score}")

display_result("Aisha", 84)
```

The procedure is named `display_result`. Its inputs are `name` and `score`.

## Functions

A function returns a value to the code that called it.

```python linenums="1"
def calculate_percentage(mark, total):
    percentage = mark / total * 100
    return percentage

result = calculate_percentage(42, 50)
```

The function is named `calculate_percentage`. It receives two inputs and
returns one output.

| Feature | Procedure | Function |
|---|---|---|
| Performs a task | Yes | Yes |
| Can receive parameters | Yes | Yes |
| Returns a value used by the caller | No | Yes |
| Typical call | `display_result(name, score)` | `result = calculate_percentage(mark, total)` |

## Connecting Design to Code

The design notation:

```text
Calculate percentage
IN: mark, total
OUT: percentage
```

can be implemented as:

```python
def calculate_percentage(mark, total):
    return mark / total * 100
```

The module name, inputs and output should agree with the design.

!!! tip "Higher checklist"

    Be ready to identify a sub-program's name, arguments, formal and actual
    parameters, inputs, outputs and local variables from code.
